# Quick Work Log 機能仕様書

- 文書バージョン: v0.1
- 作成日: 2026-09-18
- 対象要件: `Quick_Work_Log_要件定義書_v0.2.md`
- 対象計画: `Quick_Work_Log_実装計画書_v0.1.md`

## 1. 本書の目的

本書は「Quick Work Log」の初回版について、要件定義書で確定した内容を実装可能な粒度へ具体化する。

要件定義書は「何を実現するか」、実装計画書は「どの順番で作るか」、本書は「各機能がどのように動作するか」を定義する。

本書と要件定義書が矛盾する場合は、要件定義書を優先する。実装中に仕様変更が必要になった場合は、コードだけを変更せず、要件定義書、本書、実装計画書の該当箇所を更新する。

## 2. システム概要

### 2.1 概要

Quick Work Logは、Chrome上でショートカットキーまたはツールバーアイコンから予定入力画面を開き、Google Calendar APIを通じて作業記録をGoogleカレンダーへ登録する拡張機能である。

GoogleカレンダーのWeb画面は開かない。作業カテゴリは拡張機能内で管理し、カテゴリに設定した色をGoogleカレンダー予定の色として使用する。

### 2.2 システム境界

| 区分 | 対象 |
| --- | --- |
| 拡張機能内 | 入力画面、検証、カテゴリ管理、前回値保存、認証制御、API通信、結果表示 |
| Chrome提供 | 拡張機能起動、ショートカット、Identity API、Storage API |
| Google提供 | OAuth 2.0、Calendar API、Googleカレンダー |
| 対象外 | 独自サーバー、独自DB、閲覧ページ解析、Chromeウェブストア公開 |

### 2.3 想定利用形態

- 利用者本人だけが使用する。
- デスクトップ版Google Chromeへローカル読み込みする。
- 一つのChromeプロファイルで、一つの認証済みGoogleアカウントを使用する。
- Chromeが起動している状態で使用する。

## 3. 用語

| 用語 | 定義 |
| --- | --- |
| 予定入力画面 | 拡張機能アイコンまたはショートカットから開くポップアップ |
| 作業記録 | Googleカレンダーへ登録する通常予定 |
| 作業カテゴリ | 拡張機能内で管理する、カテゴリ名と予定色の組み合わせ |
| 登録先カレンダー | 作業記録を追加するGoogleカレンダー |
| 前回値 | 直近の登録成功時に保存したカレンダーIDと場所 |
| 予定色 | Google Calendar APIのColorsリソースにあるイベント用色 |
| APIエラー | Google Calendar APIから正常応答を得られなかった状態 |

## 4. 全体構成

### 4.1 構成要素

| 構成要素 | 責務 |
| --- | --- |
| `manifest.json` | 拡張機能情報、権限、OAuth、ポップアップ、ショートカットの宣言 |
| ポップアップUI | 入力、カテゴリ管理、状態表示、登録操作 |
| UI制御 | 初期化、DOM更新、フォーカス、ボタン状態の制御 |
| 検証モジュール | 必須、日時前後関係、カテゴリ存在確認 |
| 保存モジュール | カテゴリ、前回カレンダーID、前回場所の永続化 |
| 認証モジュール | OAuthトークン取得、無効トークン除去、再認証 |
| Calendar APIモジュール | カレンダー一覧、色一覧、予定登録 |
| エラー変換モジュール | 技術的失敗を利用者向けエラーへ分類 |
| Service Worker | 拡張機能のバックグラウンド処理と将来の共通処理の受け口 |

### 4.2 処理の原則

- DOM操作をAPI通信モジュールへ含めない。
- APIレスポンスをそのままUIへ渡さず、画面表示用データへ変換する。
- `chrome.storage.local` を直接操作する箇所を保存モジュールへ集約する。
- 認証トークンをアプリ独自データとして保存しない。
- 予定登録処理は一度に一件だけ実行する。

## 5. Manifest仕様

### 5.1 基本情報

| 項目 | 値・方針 |
| --- | --- |
| `manifest_version` | `3` |
| `name` | `Quick Work Log` |
| `version` | 初回版のリリース番号を設定 |
| `action.default_popup` | 予定入力画面のHTML |
| `background.service_worker` | Service WorkerのJavaScript |

### 5.2 Chrome権限

| 権限 | 用途 |
| --- | --- |
| `identity` | Google OAuthトークンの取得と再認証 |
| `storage` | カテゴリと前回値の保存 |

`commands` はManifestのコマンド宣言として使用する。閲覧ページを操作しないため、`activeTab`、`tabs`、`scripting` およびコンテンツスクリプトは使用しない。

Google APIへのHTTP通信に必要なホスト権限は `https://www.googleapis.com/*` に限定する。

### 5.3 OAuthスコープ

| スコープ | 用途 |
| --- | --- |
| `https://www.googleapis.com/auth/calendar.calendarlist.readonly` | カレンダー一覧の取得 |
| `https://www.googleapis.com/auth/calendar.events` | 選択したカレンダーへの予定登録 |

予定色一覧の取得には、上記のカレンダー一覧読み取りスコープを利用する。全カレンダー操作権限である `https://www.googleapis.com/auth/calendar` は要求しない。

### 5.4 ショートカット

| 項目 | 仕様 |
| --- | --- |
| コマンド | `_execute_action` |
| Windows/Linux既定キー | `Alt+Shift+C` |
| macOS | Chromeによる解釈に従う。初回版の動作保証対象外 |
| 競合時 | `chrome://extensions/shortcuts` で利用者が変更する |

ショートカットとツールバーアイコンは、いずれも同じ予定入力画面を開く。

| 画面・ダイアログID | 名称 | 役割 |
| --- | --- | --- |
| SCR-01 | 予定入力画面 | 作業記録の入力、登録、状態表示 |
| DLG-01 | カテゴリ追加・編集ダイアログ | カテゴリ名と色の追加・変更 |
| DLG-02 | カテゴリ削除確認ダイアログ | カテゴリ削除の最終確認 |

## 7. SCR-01 予定入力画面仕様

### 7.1 画面目的

一つのポップアップ内で作業記録に必要な項目を入力し、Googleカレンダーへ登録する。

### 7.2 表示順

1. 画面タイトル
2. 全体メッセージ領域
3. 作業名
4. 開始日・開始時刻
5. 終了日・終了時刻
6. 作業内容・メモ
7. 登録先カレンダー
8. 場所
9. 作業カテゴリと管理操作
10. 登録ボタン

### 7.3 入力項目

| 項目ID | 項目名 | UI | 必須 | 初期値 | Google予定項目 |
| --- | --- | --- | --- | --- | --- |
| FLD-01 | 作業名 | 1行テキスト | 必須 | 空欄 | `summary` |
| FLD-02 | 開始日 | 日付 | 必須 | 端末の当日 | `start.dateTime`の元値 |
| FLD-03 | 開始時刻 | 時刻 | 必須 | 空欄 | `start.dateTime`の元値 |
| FLD-04 | 終了日 | 日付 | 必須 | 端末の当日 | `end.dateTime`の元値 |
| FLD-05 | 終了時刻 | 時刻 | 必須 | 空欄 | `end.dateTime`の元値 |
| FLD-06 | 作業内容・メモ | 複数行テキスト | 任意 | 空欄 | `description` |
| FLD-07 | 登録先カレンダー | 選択 | 必須 | 前回値が有効なら選択 | URL内の`calendarId` |
| FLD-08 | 場所 | 1行テキスト | 任意 | 前回の場所 | `location` |
| FLD-09 | 作業カテゴリ | 選択 | 必須 | 未選択 | `colorId`の参照元 |

### 7.4 ボタン・操作

| 操作ID | 表示 | 動作 |
| --- | --- | --- |
| ACT-01 | 登録 | 入力検証後、予定登録を開始する |
| ACT-02 | カテゴリ追加 | DLG-01を追加モードで開く |
| ACT-03 | カテゴリ編集 | 選択中カテゴリをDLG-01で開く |
| ACT-04 | カテゴリ削除 | 選択中カテゴリを対象にDLG-02を開く |
| ACT-05 | 再認証 | 対話的なGoogle認証を開始する |

カテゴリが未選択の場合、編集と削除は無効にする。

### 7.5 初期フォーカス

- 通常時は作業名へフォーカスする。
- 再認証が必要で入力画面を使用できない場合は再認証ボタンへフォーカスする。
- 致命的な初期化エラー時はメッセージ領域へフォーカスを移し、支援技術へ通知する。

### 7.6 Tab移動順

画面の表示順と一致させる。カテゴリの追加・編集・削除操作はカテゴリ選択欄の直後、登録ボタンは最後とする。

### 7.7 初期化処理

予定入力画面を開いたとき、次の順で処理する。

1. UIを初期化し、日付へ端末の当日を設定する。
2. `chrome.storage.local` からカテゴリと前回値を読み込む。
3. 保存済みカテゴリを表示する。
4. 前回の場所を表示する。
5. Google認証状態を確認する。
6. 認証可能な場合、カレンダー一覧と予定色一覧を取得する。
7. カレンダー一覧を名前順に表示する。
8. 前回カレンダーIDが現在の一覧にあれば選択する。
9. 利用可能な前回カレンダーがなければ未選択にし、案内を表示する。
10. 作業名へフォーカスする。

カレンダー取得中も、APIに依存しない入力欄は入力可能とする。ただし登録先カレンダーを確定できるまで登録ボタンは有効にしない。

## 8. カテゴリ管理仕様

### 8.1 カテゴリ追加・編集

| 項目ID | 項目 | UI | 必須 | 仕様 |
| --- | --- | --- | --- | --- |
| CAT-01 | カテゴリ名 | 1行テキスト | 必須 | 前後空白を除去して保存 |
| CAT-02 | 予定色 | 色見本付き選択 | 必須 | APIから取得したイベント色をすべて表示 |

### 8.2 色表示

- `GET /calendar/v3/colors` のレスポンスにある `event` セクションを使用する。
- 各選択肢には色見本と識別可能な文字ラベルを表示する。
- 色だけを見分ける必要がないよう、ラベルまたは色IDを併記する。
- APIから取得できなかった場合、新規カテゴリの追加と色変更を無効にし、既存カテゴリは表示のみ可能とする。

### 8.3 カテゴリ名の正規化

保存前に次を行う。

1. 先頭と末尾の空白を除去する。
2. 正規化後が空文字ならエラーとする。
3. 大文字・小文字を区別しない比較用文字列を生成する。
4. 追加時は全カテゴリ、編集時は自分以外のカテゴリと比較する。
5. 同名が存在する場合は保存しない。

日本語、英数字、記号の利用を許可する。初回版ではカテゴリ名の文字数上限を独自に設けない。

### 8.4 追加

- 保存成功後、カテゴリ一覧へ反映する。
- 新規作成したカテゴリを作業カテゴリの選択値にする。
- 保存失敗時はダイアログを閉じず、入力を保持する。

### 8.5 編集

- カテゴリIDは変更しない。
- カテゴリ名、色ID、更新日時を変更する。
- 編集結果は次回以降の予定登録に使用する。
- Googleカレンダーに登録済みの予定は更新しない。

### 8.6 削除

- DLG-02にカテゴリ名を表示して確認する。
- 確認後、ローカル保存から対象カテゴリを削除する。
- 削除対象が選択中の場合、作業カテゴリを未選択へ戻す。
- 登録済みGoogleカレンダー予定は削除・更新しない。

### 8.7 初回状態

初期カテゴリは0件とする。カテゴリが0件の場合は、作業カテゴリ欄に「カテゴリを追加してください」と表示し、登録ボタンを無効にする。

## 9. カレンダー一覧仕様

### 9.1 API

- メソッド: `GET`
- URL: `https://www.googleapis.com/calendar/v3/users/me/calendarList`
- `minAccessRole=writer` を指定する。
- `showDeleted=false` とする。
- `showHidden=false` とする。
- `nextPageToken` が返された場合は全ページを取得する。

### 9.2 表示対象

APIが返した項目のうち、予定を書き込めるアクセス権を持つカレンダーを表示する。APIパラメータに加え、取得結果のアクセス権も確認する。

### 9.3 並び順

- 表示名を利用者のロケールで昇順に並べる。
- 大文字・小文字の差によって不自然な分離が起きない比較方法を使用する。
- 同じ表示名の場合はカレンダーIDで安定した順序にする。

### 9.4 前回値

- 保存済みの前回カレンダーIDと一致する項目があれば選択する。
- 一致しなければ未選択とする。
- 不一致時は「前回使用したカレンダーを利用できません。登録先を選択してください。」と表示する。

### 9.5 毎回取得

画面を開くたびに全件を取得する。一覧そのものは永続保存しない。

## 10. 認証仕様

### 10.1 初回認証

1. 非対話モードでトークン取得を試みる。
2. トークンを取得できない場合は、再認証が必要であることを表示する。
3. 利用者が再認証を実行したときだけ対話モードで認証する。
4. 認証成功後、カレンダー一覧と予定色一覧を取得する。

画面を開いただけで予期しない認証画面を自動表示しない。

### 10.2 認証失効

- APIから認証失敗が返された場合、使用中トークンをChrome Identity APIのキャッシュから除去する。
- 自動で対話的認証を開始しない。
- 入力内容を保持して再認証ボタンを表示する。
- 再認証後、カレンダー一覧を再取得する。

### 10.3 認証情報の扱い

- アクセストークンを `chrome.storage.local` へ保存しない。
- トークンをコンソール、画面、エラーメッセージへ出力しない。
- トークンをGoogle以外へ送信しない。

## 11. 入力検証仕様

### 11.1 検証タイミング

- 登録ボタン選択時に全項目を検証する。
- 一度エラーになった項目は、値変更時に再検証して解消表示する。
- API通信前に検証が成功していることを必須とする。

### 11.2 検証規則

| 検証ID | 対象 | 条件 | エラー文言 |
| --- | --- | --- | --- |
| VAL-01 | 作業名 | 前後空白を除去した値が空 | 作業名を入力してください。 |
| VAL-02 | 開始日 | 未入力または無効 | 開始日を入力してください。 |
| VAL-03 | 開始時刻 | 未入力または無効 | 開始時刻を入力してください。 |
| VAL-04 | 終了日 | 未入力または無効 | 終了日を入力してください。 |
| VAL-05 | 終了時刻 | 未入力または無効 | 終了時刻を入力してください。 |
| VAL-06 | 開始・終了 | 終了日時が開始日時以前 | 終了日時は開始日時より後にしてください。 |
| VAL-07 | カレンダー | 未選択 | 登録先カレンダーを選択してください。 |
| VAL-08 | カレンダー | 現在の取得一覧に存在しない | 登録先カレンダーを選び直してください。 |
| VAL-09 | カテゴリ | 未選択 | 作業カテゴリを選択してください。 |
| VAL-10 | カテゴリ | 現在の保存一覧に存在しない | 作業カテゴリを選び直してください。 |

### 11.3 日時生成

1. 日付と時刻を端末のローカル日時として結合する。
2. JavaScriptの日時オブジェクトへ変換する。
3. 実在しない日時または変換に失敗した値を無効とする。
4. 開始と終了を時刻値で比較する。
5. Calendar API送信用にはRFC 3339互換の日時へ変換する。
6. `Intl.DateTimeFormat().resolvedOptions().timeZone` で取得したIANAタイムゾーン名を `timeZone` へ設定する。

## 12. 予定登録仕様

### 12.1 API

- メソッド: `POST`
- URL: `https://www.googleapis.com/calendar/v3/calendars/{calendarId}/events`
- `{calendarId}` はURLエンコードする。
- 通知対象の参加者を使用しない。
- 添付ファイル、会議情報、繰り返し情報は送信しない。

### 12.2 リクエスト対応

| 入力・内部値 | Calendar APIイベント項目 | 変換 |
| --- | --- | --- |
| 作業名 | `summary` | 前後空白を除去 |
| 作業内容・メモ | `description` | 入力値をそのまま使用。空欄時は省略可 |
| 場所 | `location` | 入力値を使用。空欄時は省略可 |
| 開始日時 | `start.dateTime` | RFC 3339互換日時 |
| 端末タイムゾーン | `start.timeZone` | IANAタイムゾーン名 |
| 終了日時 | `end.dateTime` | RFC 3339互換日時 |
| 端末タイムゾーン | `end.timeZone` | IANAタイムゾーン名 |
| カテゴリの色ID | `colorId` | 文字列として設定 |

`eventType` を指定する場合は通常予定を示す `default` とする。終日予定用の `start.date` と `end.date` は使用しない。

### 12.3 登録開始

1. 全入力値を検証する。
2. 登録中フラグを確認する。
3. 登録中でなければフラグを有効にする。
4. 登録ボタン、カテゴリ操作、再認証操作を無効にする。
5. 「登録しています…」と表示する。
6. 認証トークンを取得する。
7. 予定登録APIを一度だけ呼び出す。

### 12.4 登録成功

1. APIが成功レスポンスを返したことを確認する。
2. 前回カレンダーIDを登録先カレンダーIDで更新する。
3. 前回場所を現在の場所で更新する。空欄の場合も空文字として更新する。
4. 「登録しました。」と表示する。
5. 短時間表示した後、ポップアップを閉じる。

成功メッセージの表示時間は初回実装時に操作確認し、視認できる範囲で固定する。値は定数として管理し、複数箇所へ直書きしない。

### 12.5 登録失敗

- 登録中フラグを解除する。
- 入力内容を変更しない。
- 前回カレンダーIDと場所を更新しない。
- 自動再試行しない。
- エラー種別と次に行う操作を表示する。
- 安全に再実行できると判断できる場合だけ登録ボタンを再度有効にする。
- 登録結果が不明な通信失敗では、その可能性を明示する。

### 12.6 二重登録防止

- 登録中フラグが有効な間は新しい登録要求を開始しない。
- 登録ボタンを無効化するだけでなく、処理関数側でも登録中フラグを確認する。
- Enterキーや連続クリックなど、異なる操作経路からの重複実行も同じフラグで防止する。

## 13. ローカル保存仕様

### 13.1 保存先

`chrome.storage.local` を使用する。`window.localStorage` は使用しない。

### 13.2 保存キー

| キー | 型 | 内容 | 初期値 |
| --- | --- | --- | --- |
| `schemaVersion` | number | 保存形式の版 | `1` |
| `categories` | array | カテゴリ一覧 | `[]` |
| `settings` | object | 前回値 | 下記参照 |

### 13.3 カテゴリ形式

```json
{
  "id": "UUID",
  "name": "開発",
  "colorId": "1",
  "createdAt": "RFC3339形式",
  "updatedAt": "RFC3339形式"
}
```

- `id` は `crypto.randomUUID()` で生成する。
- `name` は正規化後の表示名を保存する。
- `colorId` はGoogle Calendar APIのイベント色IDを文字列で保存する。
- 日時はUTCのRFC 3339形式で保存する。

### 13.4 設定形式

```json
{
  "lastCalendarId": null,
  "lastLocation": ""
}
```

- 初回のカレンダーIDは `null` とする。
- 初回の場所は空文字とする。
- 予定登録が成功した場合だけ更新する。

### 13.5 保存失敗

- カテゴリ保存失敗時はカテゴリ操作を未完了とし、画面表示を保存前の状態へ戻す。
- 予定登録成功後に前回値の保存だけ失敗した場合、予定登録自体は成功として扱う。
- 前回値を保存できなかった旨を成功表示へ付加し、自動再送は行わない。

## 15. エラー仕様

### 15.1 エラー分類

| エラーID | 分類 | 例 | 利用者への対応 |
| --- | --- | --- | --- |
| ERR-INPUT | 入力不備 | 必須未入力、日時逆転 | 該当項目を修正する |
| ERR-AUTH | 認証 | トークンなし、401 | 再認証する |
| ERR-PERMISSION | 権限 | 403、書き込み不可 | 権限またはカレンダーを確認する |
| ERR-NETWORK | 通信 | オフライン、到達不能 | 接続確認後に手動再実行する |
| ERR-CALENDAR | カレンダー利用不可 | 404、削除済み | カレンダーを選び直す |
| ERR-RATE | 利用制限 | 429 | 時間を置いて手動再実行する |
| ERR-STORAGE | 保存 | `chrome.storage`失敗 | 入力保持、手動再操作する |
| ERR-API | その他API | 400、5xxなど | 内容確認後に手動再実行する |
| ERR-UNKNOWN | 不明 | 分類できない例外 | 入力保持、再起動またはログ確認を案内する |

### 15.2 HTTP状態と分類

| HTTP状態 | 基本分類 | 補足 |
| --- | --- | --- |
| 400 | ERR-API | 送信内容の不整合として扱う |
| 401 | ERR-AUTH | トークン除去後に再認証を案内 |
| 403 | ERR-PERMISSION | 理由が利用制限ならERR-RATEへ分類可能 |
| 404 | ERR-CALENDAR | 登録先を再取得・再選択 |
| 409 | ERR-API | 自動再送しない |
| 429 | ERR-RATE | 自動再試行しない |
| 500〜599 | ERR-API | 時間を置いた手動再実行を案内 |

レスポンス本文に認証情報や予定本文が含まれる可能性を考慮し、APIレスポンス全体を利用者向け画面や通常ログへ出力しない。

### 15.3 通信結果不明

リクエスト送信後に通信が切れたなど、予定が登録されたか判別できない場合は次を表示する。

> 登録結果を確認できませんでした。Googleカレンダーを確認してから、必要な場合だけ再登録してください。

この状態では自動再試行しない。

## 16. アクセシビリティ仕様

- すべての入力項目へ明示的なラベルを関連付ける。
- 必須項目は文字でも示す。
- エラーは色、アイコンだけでなく文章で示す。
- 全体メッセージ領域は状態変化を支援技術へ通知できる構造にする。
- ダイアログを開いた際は最初の入力要素へフォーカスする。
- ダイアログを閉じた際は呼び出し元操作へフォーカスを戻す。
- Escapeキーで未保存のカテゴリダイアログを閉じられるようにする。
- 削除確認では既定フォーカスを削除実行ではなくキャンセルへ置く。
- キーボードだけで予定登録とカテゴリ管理を完了できるようにする。

## 17. セキュリティ・プライバシー仕様

- Manifestへ必要最小限の権限だけを記載する。
- 外部JavaScriptを読み込まず、拡張機能パッケージ内のコードだけを実行する。
- HTML文字列として利用者入力を挿入せず、テキストとして表示する。
- 認証トークンを永続保存しない。
- 予定内容、場所、カテゴリをGoogle Calendar API以外へ送信しない。
- 予定内容、場所、認証情報を通常ログへ出力しない。
- Content Security Policyを緩和するインラインスクリプトや`eval`を使用しない。
- カレンダーIDはURLへ設定する前にエンコードする。

## 18. ログ仕様

### 18.1 記録可能な内容

- 処理段階を示す固定文字列
- 内部エラー分類ID
- HTTP状態コード
- 発生日時
- 開発時に必要な、個人情報を含まない固定情報

### 18.2 記録禁止

- OAuthアクセストークン
- Googleアカウントのメールアドレス
- カレンダーID
- 作業名
- 作業内容・メモ
- 場所
- APIリクエスト本文全体
- APIレスポンス本文全体

初回版では外部ログ収集サービスを使用しない。

## 19. API通信仕様

### 19.1 共通

- 認証済みリクエストは `Authorization: Bearer {token}` を使用する。
- JSON送信時は `Content-Type: application/json` を設定する。
- 成功・失敗にかかわらずHTTP状態を確認する。
- API呼び出しは自動再試行しない。
- 画面を閉じた後に不要なUI更新を行わない。

### 19.2 使用API

| API | 用途 | 呼び出しタイミング |
| --- | --- | --- |
| `GET /calendar/v3/users/me/calendarList` | カレンダー一覧 | 画面を開くたび |
| `GET /calendar/v3/colors` | 予定色一覧 | 画面初期化時 |
| `POST /calendar/v3/calendars/{calendarId}/events` | 予定登録 | 登録操作時 |

### 19.3 自動再試行

すべてのAPIで自動再試行を行わない。再実行は利用者の明示操作による。

関数名は実装時に変更してよいが、責務と入出力は次を満たす。

### 20.1 保存モジュール
